# Apple API review — 15 November 2026

Checked against installed Xcode 27.2/macOS 27.2 SDK headers and official Apple documentation; the entire app and extension compile against that SDK. Deployment target is macOS 27.0, arm64.

- [Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass): standard navigation, controls, sheets and bars adopt system material automatically. Use NavigationSplitView/grouped forms, not custom glass behind reading content. Native components adapt to Reduce Motion/Transparency; actual assistive testing is separate.
- [Glass button styles](https://developer.apple.com/documentation/swiftui/primitivebuttonstyle/glass) and [prominent glass](https://developer.apple.com/documentation/swiftui/primitivebuttonstyle/glassprominent): verified in the installed SwiftUI interface and compiled. Dialog actions use these native styles within `GlassEffectContainer`; readable fields remain on semantic control backgrounds.
- [Finder Sync guide](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/Finder.html): explicit directory scope; blank-space versus selected-item menu kinds; targeted/selected URLs only during menu construction/actions; long-lived lightweight extensions. This archived guide is reconciled with current FinderSync.h rather than treated as a promise of universal coverage. `isExtensionEnabled` and `showExtensionManagementInterface` are in the installed public header.
- [NSWorkspace](https://developer.apple.com/documentation/appkit/nsworkspace): discover compatible app URLs and dispatch with `open(_:withApplicationAt:configuration:completionHandler:)`. Do not change defaults for a proof. Signaling an open request successfully does not establish a signed-in account/profile.
- [NSApplicationDelegate URL events](https://developer.apple.com/documentation/appkit/nsapplicationdelegate/application(_:open:)): current NSApplication.h declares `application:openURLs:`. The proof exercises incoming events, not just a text field.
- [ImageIO](https://developer.apple.com/documentation/imageio): native image source validation, orientation-aware thumbnails at source dimensions, and PNG destinations. Native supports more formats, but MVP only promises its tested bounded pair.

Signing: no valid local code-signing identities were reported by `security find-identity -v -p codesigning`. Ad-hoc builds and Finder registration worked locally. This is not Developer ID/notarization acceptance.

Clipboard-to-file review: installed `NSPasteboard.h` confirms `pasteboardItems`, PNG/TIFF types, `changeCount` and `accessBehavior`, including user-originated paste access semantics. Apple’s [pasteboard data documentation](https://developer.apple.com/documentation/appkit/nspasteboard/data(fortype:)) describes missing data after changes/timeouts; [changeCount](https://developer.apple.com/documentation/appkit/nspasteboard/changecount) tracks ownership changes. Capture handles missing/changed/denied content and never modifies clipboard permissions. [ImageIO thumbnail creation](https://developer.apple.com/documentation/imageio/cgimagesourcecreatethumbnailatindex(_:_:_:)) is used on a worker for orientation-aware image rendering and a bounded preview.

Image-conversion expansion: [CGImageDestinationCopyTypeIdentifiers](https://developer.apple.com/documentation/imageio/cgimagedestinationcopytypeidentifiers%28%29) discovers native encoders. [CGImageDestination](https://developer.apple.com/documentation/imageio/cgimagedestination) writes PNG/JPEG/HEIC; `kCGImageDestinationLossyCompressionQuality` controls JPEG/HEIC compression. A local Swift probe encoded and decoded all three formats, including HEIC. Core Graphics explicitly composites white/black backgrounds in an 8-bit sRGB bitmap; captured pixel data is reused for preview and publication. The 34-test suite validates the twelve supported input/output combinations and pixel-level transparency/background behavior on this host.

PDF assembly uses [PDFDocument.insert(_:at:)](https://developer.apple.com/documentation/pdfkit/pdfdocument/insert%28_%3Aat%3A%29) with copied PDFPage instances; the installed header specifically recommends copying before insertion. Page boxes and rotation are preserved. [PDFDocument permission properties](https://developer.apple.com/documentation/pdfkit/permission-properties) support rejecting protected documents, and the catalog is checked for form/signature structures. PDFPage thumbnails include annotations; all PDFKit objects remain local to their worker. Core Graphics supplies A4 image pages. Tests create annotation fixtures on the main actor while explicitly executing preparation/assembly in detached tasks, avoiding fixture-only AppKit teardown warnings.

Copy As uses the existing public NSPasteboardItem/setString and NSPasteboard.writeObjects APIs. The formatter only handles URL/string values; it does not launch a shell, resolve file URLs or read clipboard contents.


QR creation review (16 November 2026): installed CoreImage `CIFilterBuiltins.h` confirms the typed [CIQRCodeGenerator](https://developer.apple.com/documentation/coreimage/ciqrcodegenerator) `message: Data` and M/H correction properties. Core Graphics supplies integer scaling and the white border; ImageIO supplies the final PNG. Tests use [VNDetectBarcodesRequest](https://developer.apple.com/documentation/vision/vndetectbarcodesrequest) and [VNBarcodeObservation](https://developer.apple.com/documentation/vision/vnbarcodeobservation) for independent decoding. The installed `CIBarcodeDescriptor.h` documents error-corrected QR codewords, which the BOM test inspects separately from the scanner's display string. `CIDetectorTypeQRCode` supplies a second native decoder for dense output. Actual compile/scan results and scanner differences are recorded in [QR verification](verification/QR-CREATION.md).

QR reading review (16 November 2026): the installed Vision and Core Image headers confirm QR-only detection, optional decoded text and image bounds. Apple documents [normalized Vision bounding boxes](https://developer.apple.com/documentation/vision/vndetectedobjectobservation/init(boundingbox:)) with a bottom-left origin. [CIQRCodeFeature](https://developer.apple.com/documentation/coreimage/ciqrcodefeature) uses image-coordinate bounds and an optional `messageString`; the reader normalizes these to the same image before merging. [CIDetectorTypeQRCode](https://developer.apple.com/documentation/coreimage/cidetectortypeqrcode) supplies the additional native detector. ImageIO handles orientation before both detectors run. These APIs compile and decode synthetic fixtures on the installed SDK; [verification](verification/QR-READING.md) records supported format checks, dense-code recovery and remaining coverage.
