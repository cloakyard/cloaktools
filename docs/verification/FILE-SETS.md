# File sets and folder templates

Verified 15 November 2026 on macOS 27.2.1 (26B131), Apple silicon, Xcode 27.2 / macOS 27.2 SDK / Swift 6.4.2. Native local preview **0.4.1 (14)**. This is development evidence, not a public-release claim.

## Working path and design

**File → New File Set… (⇧⌘N)**, General Quick Actions and **New Files → File sets & folder templates** open the workflow. Choose a parent destination, edit the new folder name, then add/edit/remove relative file and folder paths. Starting examples cover Notes, Python, Rust and C++. They are file collections, without generated build systems or installed dependencies; every built-in type and imported single-file template is available in the item editor.

The native window is 560 × 560 pt of content, with a declared 500 × 500 minimum. Item and Save Set sheets are 440 pt wide. Readable cards separate the folder name and scrollable contents. Destination, feedback and Glass actions stay outside that scroller. Each path has a content description and labeled edit/remove actions. The list scrolls to added/edited items, reserves room for the scrollbar, and counts implicit parent folders. Programming controls appear only for built-in code.

**Review…** prepares exact bytes off the main actor without writing output. The next step lists the paths, content descriptions, byte total and destination, explains numbered collisions, and requires **Create Folder**. Back returns to editing; Change can choose another parent without regenerating the review. **Save Set…** saves a reusable definition only; an existing definition uses **Update saved set / Save Changes**. Removal leaves output and source templates intact.

## Publication and limits

`FileSetDefinition` validates paths, identifiers and metadata. `PreparedFileSet` owns the generated bytes and honors captured global/per-language Hello World precedence. Always blank can further suppress built-in code; custom content remains exact, and JSON/PDF retain valid structure.

Publication builds a private sibling staging folder, writes its files/subfolders, checks cancellation between entries, then uses exclusive rename to publish the complete root. Name collisions produce a numbered root, including concurrent requests and symlink collisions. Existing folders are never merged. Normal cancellation/failure removes staging; a successful final rename wins over a later cancellation. A crash can leave a hidden staging folder.

Limits: 32 saved definitions, 32 entries per set, 8 path levels, 120 bytes per path component, and 16 MiB of prepared content. Persistence uses a bounded 2 MiB JSON file. Unsafe paths, hidden names, traversal, conflicting case/canonical-Unicode paths, file/parent conflicts and extension/type mismatches are rejected. Existing folder import, symbolic links, direct merging, hidden configuration files, build-system generation and a dedicated Finder action are outside this slice. Saved sets reference imported templates; removing a referenced template requires choosing a replacement. No folder access grant or Finder scope change is added.

## Remaining verification

- The live pass covered editing, validation, saving, persistence, review, destination changes, cancellation of drafts and repeated publication. Mid-staging cancellation was deterministic in the core test, not timed manually against these tiny live sets.
- Spoken VoiceOver, light appearance, Reduce Transparency/increased contrast, minimum-size interaction, long-label/localization stress and all 32-row combinations remain broader release checks.
- Cloud providers, disk-full errors, abrupt termination/recovery, hostile same-user filesystem mutation and every cancellation/publication race are not exhaustively verified. Atomic publication depends on the destination filesystem supporting the native exclusive rename operation; a failure is surfaced rather than merged or overwritten.
- Developer ID signing/notarization, installer/update lifecycle, supported App Group Finder scopes and Edge/profile routing remain open as recorded in the roadmap. The next feature is reviewed reusable export recipes.
